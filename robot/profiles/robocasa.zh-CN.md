驱动：`robocasa`

本构型使用 RoboCasa 中的 PandaOmron 移动操作机器人。驱动支持 `vla_execute`、
`move_to_pose`、`move_linear` 和 `set_gripper`。
使用 `object_location` 和 `task_verification` 为规划提供依据并检查操作结果。


**记得及时更新计划。**

应根据规划阶段及时更新和检查计划。

## 成功检查

每次 `execute_robot_action` 后，重新读取 `ROBOT_STATE.md`。
如果最新的 `robots.robocasa.success` 为 `true`，立即停止。
否则重新评估当前子目标，必要时使用 `task_verification`。动作调用完成不代表任务成功。

如果 `robots.robocasa.done` 为 `true`，或 `robots.robocasa.ready`
为 `false`，停止发送机器人动作。

## 任务路线

根据当前子目标选择适用的路线。组合任务按原始指令组织多个阶段，
从当前已达到的状态继续，保留尚未完成的物体、空间关系和设备状态要求。

### 固定结构与大型目的地

根据任务和当前场景识别目标结构及其实际操作部位：

- 橱柜、抽屉和冰箱：区分门、抽屉、内部空间与指定层架。
- 微波炉和小烤箱：区分门、内部放置区域、启动按钮与定时旋钮。
- 洗碗机：区分门、滑动碗架与餐具放置区域。
- 炉灶：区分目标炉头及控制该炉头的旋钮。
- 水槽：区分槽内、出水口与水龙头控制部位。
- 咖啡机：区分接杯位置与启动按钮。
- 其他电器：按任务区分搅拌机盖子与杯口、厨师机机头、电水壶开关、
  烤面包机插槽与压杆。
- 台面、餐台及容器：明确最终支撑面，或篮子、托盘、碗、杯子、锅等的内部。

接近这些结构，或携物从其旁边、上方或内部通过前，调用 `object_location`
测量相关物体和结构的 `position_m`、`size_m`。按完整空间范围规划，
为夹爪和所持物体留出间隙；结构的整体包围盒不代表其内部可用空间。

让 VLA 连贯完成视觉接近、把手接触、开关门、拉动抽屉或碗架，
以及按压按钮和转动旋钮。attach 用于有测量依据的空旷空间运动。

“最初在抽屉或橱柜中”等关系如果只是识别物体的依据，且物体已可见、
可接近，就直接定位。只有操作通路需要或任务明确要求时，才开关结构。

### 可移动物体任务

普通抓取放置采用以下路线：

`定位物体 -> attach 接近 -> VLA 抓取 -> 定位目的地 -> attach 抬升与运输 -> VLA 放置`

保持同一目标实例。运输装有食物或其他物体的碗、篮子、托盘、锅和容器时，
保持所需朝向及其内容物；由 VLA 完成最终对齐、接触和释放。

当目标身份、抓持状态、操作通路或阶段结果不明确时，调用 `task_verification`。
结果已明确时继续下一阶段，不必在每个阶段之间固定插入验证调用。

### 连续接触与组合任务

清洗、刷洗、搅拌和倾倒等操作，由 VLA 完成具有完整动作语义的连贯阶段；
将工具移到目标附近并不等于完成这些操作。

组合任务依照原始指令衔接上述路线。例如：先装入食物再搬运容器，
先放好杯子再启动咖啡机，先装入餐具再关闭洗碗机。
保留物体数量、类别、相对位置、容器内容及要求的门或开关最终状态。
发生失败时，从当前状态恢复尚未完成的阶段。

## 目标身份

目标存在歧义时，结合：

`物体类别 + 视觉特征 + 原始任务关系`

### 物体外观提示

以下提示用于辅助识别。结合当前实例的形状、颜色、纹理、标签和原始任务关系，
不要把某个模型的配色当作整个类别的固定特征。

- **马克杯（mug）：** 开口杯体，侧面有杯柄；存在纯色和印花款式，
  不限定为白色，也不要与无柄玻璃杯混淆。
- **饮用杯 / 玻璃杯（cup / glass_cup）：** 无柄开口杯体，常呈圆筒或
  上宽下窄形；透明和不透明款式都有，不能仅凭透明度判断目标。
- **碗（bowl）：** 有明显深度的开口容器，弧形侧壁围成内腔；
  不要与浅盘、托盘或倒扣的盖子混淆。
- **盘子（plate）：** 浅而宽的圆形器皿，有低矮盘沿；
  存在纯色和花纹款式。
- **滤盆（colander）：** 碗状容器，盆壁或底部有密集孔洞、网格，
  可带侧柄或支脚；不要当作实心碗。
- **饭盒 / 保鲜盒（tupperware）：** 较深的盒状开口容器，常为矩形，
  有明显侧壁和内部空间；不要与低边托盘混淆。
- **托盘（tray）：** 宽而浅的平底承载面，周围有低边，部分款式带把手；
  不要当作深饭盒或没有围边的砧板。
- **篮子（basket）：** 有较深的承载空间，存在金属网和编织款式，
  可为圆形或矩形；不要仅凭棕色或某一种编织纹理识别。
- **平底锅（pan）：** 浅圆锅身配较长侧柄；不要与圆盘或深锅混淆。
- **深锅 / 汤锅（pot）：** 较深的锅身，带侧柄或耳柄；
  根据锅壁深度与把手形状区别平底锅和碗。
- **普通水壶（kettle_non_electric）：** 壶身带壶嘴和提把或侧把，
  存在金属和陶瓷款式；不要与咖啡机、杯子或带电源底座的电水壶混淆。

- **砧板（cutting_board）：** 扁平板状物，常为木纹矩形或圆角矩形，
  主要表面平坦；不要与有围边的托盘或带显示屏的电子秤混淆。
- **电子秤（digital_scale）：** 有称重平台、显示屏和控制区域的底座；
  不要将旁边的砧板或普通托盘当作称重平台。
- **刀（knife）：** 刀柄连接扁平、较长的刀刃；不要与只有细长杆身的
  吸管、勺柄或串签混淆。
- **削皮器（peeler）：** 手柄连接带开口的刀架，刀片位于刀架中；
  存在 Y 形款式，不是具有完整长刀刃的刀。
- **锅铲（spatula）：** 长柄末端连接扁平、较宽的铲面；
  不要与末端呈凹勺状的勺子或汤勺混淆。
- **叉子、勺子和汤勺（fork / spoon / ladle）：** 分别依据叉齿、
  浅凹勺面和较深勺头识别；颜色和柄长不能单独决定类别。
- **夹子 / 打蛋器（tongs / whisk）：** 夹子有相对的夹臂；
  打蛋器末端是线圈或笼状结构，不是实心铲面。
- **海绵（sponge）：** 有厚度和多孔质感的块状物，存在绿黄双层、
  单色和圆角款式；不要与薄片食品或棱角分明的冰块混淆。
- **吸管（straw）：** 很细的长管，可有弯折，颜色不固定；
  不要与刀、餐具柄或串有食物的签子混淆。

- **整块面包（bread）：** 存在圆形面包和不规则面包块，表面有烘烤外壳、
  裂纹或切口；不要默认所有面包都是方形吐司。
- **吐司片（sandwich_bread）：** 扁平的近方形面包片，浅色内芯外有
  较深的面包边；不要与整块面包或热狗面包混淆。
- **可颂（croissant）：** 金黄至棕色，表面有卷起的层次和横向纹理，
  可呈弯月形或短梭形；不要与圆形纸杯蛋糕混淆。
- **法棍 / 热狗面包（baguette / hotdog_bun）：** 都可能呈长条形；
  法棍常有表面切纹，热狗面包有沿长轴切开的夹槽。
  结合实际切口和任务名称区分。
- **煎饼 / 华夫饼（pancake / waffle）：** 煎饼为扁圆饼或叠放的饼层，
  可带酱料；华夫饼表面有明显压出的网格。
- **纸杯蛋糕（cupcake）：** 下部为杯状蛋糕体或纸托，上部可见隆起的
  奶油、糖霜或装饰；不是层叠的煎饼。
- **香肠 / 肉串（sausage / kebab_skewer）：** 香肠是连续的长条肉制品；
  肉串有串杆和穿在杆上的食物块，不能只按长条轮廓判断。
- **鸡腿（chicken_drumstick）：** 一端为较粗的肉部，另一端逐渐收细为
  腿骨或骨柄；不要与粗细较均匀的香肠混淆。
- **肉排（steak）：** 扁平或有厚度的肉块，可见肉纹、脂肪边或烤纹；
  生熟款式颜色不同，不应只凭红色或棕色识别。

- **生菜（lettuce）：** 可见褶皱叶片、层叠叶缘或叶脉，
  存在整颗和叶片状款式；不要与表面由密集花蕾组成的西兰花混淆。
- **西兰花（broccoli）：** 有密集颗粒状花冠和较粗菜梗，
  不同于生菜展开或卷曲的叶片。
- **胡萝卜（carrot）：** 橙色为主的细长锥形根部，一端逐渐变尖，
  部分带绿色叶柄；不要与两端较圆的黄瓜混淆。
- **黄瓜 / 茄子（cucumber / eggplant）：** 黄瓜多为两端较圆的长条形，
  可有纵纹；茄子可呈长形或圆形，通常有较明显的萼部。
  结合形状、表皮和任务名称识别。
- **草莓（strawberry）：** 红色为主，表面有密集籽点，外形趋向锥形或心形；
  绿色叶冠并非每个实例都清楚可见。
- **柠檬角（lemon_wedge）：** 扇形或楔形果肉，外弧包着果皮；
  本素材库存在绿色模型，不能因为不是黄色就排除。
- **冰块（ice_cube）：** 白色或半透明的有棱角块体，常接近立方体；
  不要与有细孔纹理的海绵或有果皮的水果块混淆。

- **番茄沙司及调味瓶（ketchup / condiment_bottle）：** 结合酱料颜色、
  瓶体轮廓、瓶盖和可读标签识别；存在扁瓶、细长瓶和不同包装。
- **调味罐 / 撒料罐（shaker）：** 多为较短的罐状容器，
  重点观察撒料顶盖及罐体；不要仅按颜色与普通调味瓶区分。
- **果酱（jam）：** 带盖的罐装或杯装食品，存在玻璃罐和塑料杯包装；
  结合标签、盖子与内容物识别，不要假定一定透明或一定带格纹盖。
- **瓶装水（bottled_water）：** 常见旋盖、瓶身环纹和环绕标签；
  不要仅凭透明瓶身判断其属于水瓶。
- **酒类瓶（alcohol）：** 包含啤酒、葡萄酒等不同实例，瓶形、颜色和标签
  不统一；与瓶装水区分时结合瓶颈、瓶盖、标签和任务中的参照组。
- **盒装 / 袋装食品（boxed_food / bagged_food）：** 分别依据硬质盒体与
  柔性袋状包装识别；具体食品以当前可读标签和原始指令为准。

- **搅拌机盖子（blender lid）：** 与搅拌杯口匹配的扁平盖状物，
  部分带中心凸起或旋钮；不要与杯体、机器底座或旁边的盘子混淆。

### 身份绑定与跟踪

- 使用原始任务关系绑定实例，例如“最初在水槽旁边的杯子”或“最初在左侧橱柜中的碗”。
- 对外观相同的物体，使用初始关系和位置绑定身份。当任务用初始左右关系识别物体时，
  保留该角色；相机或机器人视角变化不会重新定义这些角色。
- 物体移动后，通过观测到的运动、动作历史和最后已知位置跟踪同一实例。
- 源位置附近出现另一个同类别物体，不会推翻已经通过运动跟踪确定的身份。
- 如果跟踪连续性丢失，根据证据和动作历史重新建立身份。
  不要编造视觉差异，也不要悄悄换成另一个实例。

### 提供给子代理的身份信息

`object_location` 专家不会继承本 profile。每个请求都必须自包含，
提供目标的外观描述、原始任务关系、相关移动历史和必要的排除项；仅提供 cup、bowl
或 bottle 这样的类别名称是不够的。在 `task_verification` 请求中
使用同一身份信息。

## RoboCasa 控制约定

本构型使用官方的当前任务指令。每次调用 `vla_execute` 时，都必须将
`robots.robocasa.task.instruction` 原样复制为指令；当前局部阶段应写在
`PLAN.md` 和动作推理说明中，而不是改写策略提示词。`step` 是正整数的策略动作
执行预算。

遵循 attach 和 VLA 技能的动作参数、步数预算及恢复指导。

几何动作使用世界坐标系，单位为米，目标位置对应末端 grip site，
不是物体中心。当前末端位姿读取 `eef_pose_world`，四元数采用 XYZW
顺序；不要将 `eef_pose_relative` 直接用于世界坐标目标。

几何运动默认保持最后执行的夹爪命令，包括 VLA 执行后的命令。
若 `last_gripper_close` 为 `null`，根据当前抓取状态显式指定
`gripper_command`（`open` / `close`）。携带物体时保持关闭，不要为初始化而打开夹爪。

`set_gripper` 仅支持 `open` 和 `close`，不支持连续开度目标。
